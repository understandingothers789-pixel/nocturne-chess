# 0.5.7.80 bug and performance review

Reviewed move handling/rendering, candidate clearing, Maia foreground/background scheduling,
GPU fallback, caches, UCI stop/ready barriers and output limits, explorer cancellation,
SQLite persistence, and packaging. This is a broad review, not a guarantee that every
possible bug has been found.

## Fixed

- Rapid Maia navigation A → B → A could retain B as the pending request because A
  still matched the obsolete active signature. Suppression now checks request generation
  and pending work. Failed requests for the same position can also be retried.
- GPU fallback/worker stop now clear unfinished protocol bytes and obsolete background jobs.
- Non-object JSON messages are ignored instead of raising an attribute error.
- Prefetch creates histories lazily, with at most one queued position and eight cached
  skips per timer tick. Window continuation snapshots store only the UCI sequence;
  full prefixes are constructed only when dispatched. This removes quadratic retained
  history storage and unbounded cache scanning in one event-loop callback.
- Background cache writes are coalesced over five seconds and deferred during foreground
  work, with pending data flushed on stop. In-memory caches remain bounded at 128 positions.
  Cache hits refresh eviction order. Failed background jobs stop their queue rather than
  repeatedly retrying the same failing position.
- Repeated unchanged preferences no longer update SQLite rows. A check of 100 identical
  preference saves changed one row; changed preferences still persist normally.
- Python wheels/source distributions now include the Lichess font and editable source.
  Built wheel contents were inspected for both files.

## Validation

- Ruff passed across src, tests and scripts.
- Focused Maia and storage tests passed (31 total), including new navigation, retry,
  lazy queue, cache batching, fallback and unchanged-preference regressions.
- Final full local suite: 275 tests in 155 seconds, passed with five optional skips.
- Local move-response sample: first board paint began at 4.1 ms; total handler time
  was 88 ms. This is a controlled local sample, not a Windows or GPU speed guarantee.
- Final Windows CI runs the complete suite and packaged launch/model checks.
- Windows packaging runs real bundled-model predictions and GUI smoke checks.
- No physical NVIDIA/AMD hardware is available here. GPU timing, driver compatibility
  and actual GPU contention cannot be certified by this review.
