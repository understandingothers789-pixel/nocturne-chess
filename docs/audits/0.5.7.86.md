# 0.5.7.86 UI performance review

Reviewed the engine info/rendering path, Maia policy and insight updates, game-history rendering, and existing prefetch/save batching. Changes target repeated work in the UI thread.

- Cache SAN move names for the current position and policy move set. Probability and Stockfish score changes still recompute risk assessments; position, Chess960 mode, or move-set changes invalidate the names. Only one position is retained.
- Skip rebuilding the All human moves table for identical position/probability data. Keep score cells when updating engine evaluations; new PVs still replace hover data even when scores match.
- Calculate history move numbers and colors directly from the starting FEN, eliminating a legal move replay of the entire selected line each time it grows.

## Local measurements

Qt offscreen, starting position, 20 legal policy moves, 500 repeated calls after warm-up:

| UI work | Before | After |
| --- | ---: | ---: |
| Insight analysis updates | 508.67 ms | 241.68 ms |
| Identical policy-table updates | 499.52 ms | 17.26 ms |

These are UI processing measurements in one Linux environment, not inference timings or Windows/GPU guarantees. Remaining insight rendering and changing engine scores still run normally. No inference precision, search depth, or probability coverage was reduced.

Focused regressions cover cache invalidation after board mutation, added/illegal policy moves, changed probabilities, fresh PVs with unchanged scores, and move numbering for Black-to-move FENs. Full local and Windows validation is recorded in the build receipt.
